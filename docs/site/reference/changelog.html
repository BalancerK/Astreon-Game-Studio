Changelog

All packages are released together under one version number. node tools/release.js bump patch|minor|major turns "Unreleased" into the next version.

Unreleased#

  • @engine/render: running on a slow graphics card. New QUALITY_LEVELS / qualityOf, reducePost (a finishing pass reduced to a level), createDynamicResolution (the share of the screen's size kept where the card manages 60 frames a second), gpuClass / gpuName, and renderer.setRenderScale() on both 3D renderers. resize on all five renderers no longer touches the canvas when nothing changed (that emptied it and made every picture buffer again). From a game that went from 5 to 60 frames a second on an Intel UHD 630. Tests: packages/render/test/quality.test.js.
  • @engine/client: RollbackSession no longer lets the lead of the local inputs grow for good. addLocalInput gave a frame number one further on each time it was called, even when advance could not move (it was waiting), and never took a frame back when inputDelay fell, so a slow first ping or a stall left the pilot's commands that many frames late for the whole match (a game measured 117 ms on a 40 ms link). Now asking again before the session has moved gives the same frame, and a new option serverDecides (a server has the last word on every input) lets the lead follow inputDelay both ways, giving a frame again with the newest command and never for a frame the server has already decided. Tests in packages/client/test/rollback.test.js.
  • @engine/build: the bundle now behaves like the modules it is made from. (1) Every import is read first, in order, before the module's own code, as in a real module: before, an import was a constant defined where its line stood, so a call above an import line stopped the page with "Cannot access ... before initialization" in the browser only (a game's loadout page crashed live with every test passing). (2) this at the top of a module is undefined and import.meta works (import.meta.url is the module's address). (3) build stops with a clear message when a bundle does not parse. (4) New checkBundle(entry, { only }): loads every module of a bundle both as it is and bundled and compares what each exports (a missing name, an extra one, a value of another kind), so a bundler mistake is a failed test and not a broken page. (5) New tools/built-smoke.js <project>: builds the project as it ships, serves it and opens every page in headless Chrome, failing on any thrown error or failed load (tools/built-smoke-test.js tests the check).
  • @engine/ai: NavVolume, navigation through three dimensions for things that fly or move between levels. One volume per agent size; boxes mark the cubes a body cannot occupy; A* over 26 neighbours with line-of-sight smoothing; found, partial or none; deterministic. Made for Mecha Strike's bots.
  • Studio: a Tables panel. A game's rules (weapons, frames, enemies, items) kept as a plain data file (export default { "weapons": [ {...} ] }) are edited as a grid, with a box of the right kind for every column (text, number with limits, choice, tick, colour) described by a name.schema.json beside it. Cells are checked as you type (ranges, kinds, duplicate names), saved to the file, and the game picks them up like any edit; rows can be added, copied, moved and removed. Made for Mecha Strike's parts tables.
  • Studio: a Rig panel. It finds skeleton files (JSON in rigs/, in the @engine/skeleton2d format), draws them with the engine's renderer using the project's pictures (a coloured block stands in for a missing one), plays any animation with pause, speed, loop and a moment slider, shows events and (if you like) the bones, and can add a sample rig to start from.
  • Fixed a rare lost first message on browser-to-browser connections: RtcTransport now keeps messages that arrive before onMessage is set (the handler is usually set a moment after the connection opens) and delivers them, in order, when it is.
  • Studio: an Environment panel. Sliders for the sky (time of day, haze, clouds, stars), the water (level, colours, clearness, waves) and the ground (hills, roughness, land number), drawn live by the engine's own renderer (drag to turn the view, scroll to zoom) and kept in environment.json, which a game made with the engine can read to get the same sky, water and hills. Studio arcade games do not use it. The Friend panel is now in the workspaces too.
  • Studio: a Pixel art switch in Project settings (pixelArt in project.json) keeps pictures sharp when the game is scaled up, in the studio and in the exported game, plus a 320 × 180 screen preset. Without it the studio preview is now smooth like the export (it used to be always blocky).
  • Dialogue boxes understand a little markup: [b]bold[/b], [i]leaning[/i] and [color=#ff6b6b]coloured[/color] words (parseMarkup, stripMarkup, layoutMarkup, drawMarkup in the arcade kit). Tags do not count as letters for the typewriter, and the text no longer re-wraps while it is typed.
  • Arcade lights now cast shadows and can have a strong core: list the kinds of thing that block light in screen.occluders, and each light's glow is cut by their shadows (light.shadows: false opts a light out; light.core keeps full strength out to that fraction of the radius). shadowShapes is exported. The Lights panel has the matching controls. Files without these fields draw exactly as before.
  • Studio: Play with a friend panel. Two browsers join with a pair of invitation codes (WebRTC, no server), check they have the same game, and run it in lockstep, trading only held keys. Arcade kit gains Lockstep (packages/arcade/src/netplay.js) and me()/playerCount()/isOnline()/isWaiting(); a game opts in with export const players = 2 and reads inputs (4th argument of update).
  • Polish and gap closing, first pass. @engine/render: filter: 'nearest' / setFilter for pixel art on all three 2D backends; Font option kerning; Atlas.clear() with Font.reset() / BitmapFont.reset() / FontStack.reset() / RichText.reset() to recover from a full text atlas; the WebGL2 renderer links programs that lack a scene block, and compiles the sky and water shading only for createRenderer3D({ water: true }) (it made the main shader slow to compile). @engine/physics: TriWorld.addTriangles for terrain.   • Spot lights, area lights and shadows from point and spot lights (engine gap E3). The entries of lighting.pointLights can now be spot lights (direction, angle, penumbra) and rectangular area lights (type: 'area', width, height, direction, right; one-sided; shaded with the nearest point of the panel for diffuse light and the point nearest the mirror direction for highlights, scaled by the solid angle it fills), and any point or spot light can cast shadows with castShadow: true: a spot light renders one perspective depth map and a point light six (a cube), into their own array of up to 12 layers (render({ localShadows: { size, layers, bias, strength } | false })), given to the nearest lights when more ask than fit. The shadow lookup moves the surface toward the light and off itself by about a texel before a 3x3 comparison, so it needs no per-light bias tuning. DrawList3D.setCamera(camera, { lights }) keeps off-screen casters inside a shadow-casting light's reach. Both renderers share one light evaluation (localLight) in WGSL and GLSL, used by the simple and the physically based paths; point lights without the new fields shade exactly as before. The scene uniform block grew (the new per-light data and the shadow matrices sit after the cascade block, so earlier offsets did not move); the four copies of the block in the WebGL2 shaders are now one. 9 unit tests and tools/render-lights-test.js (17 checks on each of WebGPU and WebGL2: cone, soft edge, aiming, one-sided and size-scaled panels, symmetric panel light, point-light shadows in three cube faces, spot-light shadows on simple and physically based floors, a caster behind the camera, the layer budget, and WebGPU against WebGL2 on five scenes within 1.5/255).   • Ambient occlusion, depth of field and FXAA (engine gap E4). Three new post options, each off unless given and free when off, on WebGPU and WebGL2: ao (screen-space ambient occlusion from the depth buffer, with normals rebuilt from depth, a rotated hemisphere kernel, and a depth-aware separable blur; radius, intensity, power, bias, samples, scale for half-resolution), dof (thin-lens depth of field, focus, range, aperture, maxBlur, taps, with a gather that keeps a sharp foreground from bleeding into a blurred background) and fxaa (one pass on the finished picture, so it also works with antialias: false). Both renderers now keep the scene's depth as a texture when a depth effect is on (WebGL2: a depth texture resolved from the multisampled one; WebGPU: the depth texture is stored and read as a multisampled depth texture); an orthographic camera skips the depth effects. circleOfConfusion(distance, dof) is exported (the shader's own blur size, for autofocus). 7 unit tests and tools/render-postfx-test.js (WebGPU and WebGL2, each with and without multisampling: the floor at a cube's foot darkens and open floor, the top and the sky do not; half resolution works; stripes at the focus keep their sharpness while nearer and farther ones blur; range keeps a band sharp; FXAA adds in-between pixels to a staircase edge and leaves flat areas alone; everything at once draws; turning the effects off restores the plain picture exactly). Not done: temporal anti-aliasing (needs motion vectors), screen-space reflections, occlusion from things outside the screen, a near blur that spreads over a sharp background.
  • Drawing less (engine gap E5): levels of detail, occlusion culling and static merging. Levels of detail: simplifyMesh(mesh, { ratio | cellSize, keepEdges }) makes a coarser copy by vertex clustering (linear time, works on skinned meshes, a 100,000-triangle sphere to 10% in about 50 ms); createLod({ mesh, ratios, screens, cullBelow }) (or your own levels) bundles versions with the on-screen size at which each takes over, and DrawList3D.addLod / addSkinnedLod pick the level for the camera each frame (and draw nothing below cullBelow; list.lodBias shifts every choice). Occlusion culling: OcclusionBuffer is a 128 x 72 depth image drawn on the CPU from your walls and buildings (addBox, addMesh), and DrawList3D.setOcclusion drops instances whose bounding sphere is behind it (20 boxes fill in 0.09 ms, 2,000 tests cost 0.14 ms); no GPU queries, so no latency or flicker, and the same on every backend. It only drops what is certainly hidden (checked against ray casts over thousands of random scenes), and keeps everything when shadows are on, since a hidden thing can still throw a shadow into view. Merging: StaticBatcher collects placed pieces and build() merges the ones with the same colour and texture in the same grid cell into single world-space meshes (normals through the inverse transpose, mirrored pieces re-wound), drawn with DrawList3D.addBatch: 5,000 boxes become 32 batches in 9 ms. 12 unit tests and tools/render-drawless-test.js (WebGPU and WebGL2: merged batches look like the pieces drawn one by one, the LOD draws exactly what the chosen level draws, and the occluded scene is pixel-identical to the unculled one while dropping the hidden instances). Not done: switching levels without a pop (no cross-fade or hysteresis), GPU occlusion queries, occluders that cross the near plane, merging pieces with different colours (colour is per batch, not per vertex), and automatic occluder detection.
  • Video as a texture (engine gap E15). VideoTexture(set, source) keeps one layer of a 3D TextureSet showing the current frame of a <video>, canvas, ImageBitmap or VideoFrame; VideoSprite(atlas, source, { name, width, height }) does the same for a rectangle of the 2D Atlas. Call update() once per frame: it asks the video whether it has a new picture (requestVideoFrameCallback; an older browser is judged by the clock) and does nothing while it is paused, otherwise draws it with cover / contain / stretch fitting, rebuilds the mip levels in place and lets the renderer upload just that layer. New underneath: TextureSet.update(layer, image) (replace a layer's pixels without allocating; each layer has its own version, which both 3D renderers now check) and Atlas.redraw(name, draw). 7 unit tests, and tools/render-video-test.js plays a real <video> (a canvas stream going red, green, blue) as a 3D texture on WebGPU and WebGL2 and as a sprite on WebGPU, WebGL2 and Canvas2D, checking the colours come round, that only new frames are uploaded and that a paused video costs nothing. Not done: sound or playback control (the element is yours), video files decoded without an element (WebCodecs), playing a video straight into a compressed texture set, and a partial upload for 2D (the whole atlas page is uploaded again, so give video a small atlas of its own).
  • Engine-level localisation (engine gap E29): the new @engine/i18n package. Localizer holds a table per language and gives t(key, params), tn(key, count) (the right plural form for any language: CLDR names such as one / few / many from the platform's own Intl.PluralRules, or a gettext list with the Plural-Forms rule), tc(context, key) and tcn (the same word used two ways). It reads gettext .po files (msgctxt, msgid_plural, msgstr[n], continued lines, escapes, fuzzy, the Plural-Forms header, whose expression is parsed by a small safe parser and never evaluated) and CSV sheets (key, context, a column per language, thing.one / thing.other rows; tables made for the arcade kit work unchanged). Falls back from pt-BR to pt to the default language, reports each missing word once (onMissing), lists what is untranslated (missing(lang)), writes a translator's sheet (toCsv()), formats {n:number} and {names:list} for the language, and pseudo-localises (accents, a third longer, bracketed, {places} kept) to find broken layouts. 18 tests, including the real plural rules of English, French, Russian, Polish, Arabic and Japanese. Not done: ICU select / nested messages, ordinals, date and currency formats, writing .po back.
  • Tweens and timelines (engine gap E22): the new @engine/tween package. Tween moves numbers, lists of numbers (colours, vectors, typed arrays, in place), dotted paths and relative values ('+=50') on any object with a delay, repeats, yoyo, timeScale and start / update / repeat / complete callbacks; Timeline lays tweens, calls and other timelines on one clock with GSAP-style places ('-=0.2', '<', labels, 'open+=1'); Tweens plays them and drops the finished. 31 easings (sine, quad, cubic, quart, quint, expo, circ, back, elastic, bounce, each in / out / in-out) plus your own function, a CSS-style cubic bezier and steps(n). Everything is a function of its clock, so seek(t) and progress put every property exactly where it belongs (forwards or back, silently), which makes cutscenes scrubbable and replays exact. Built from + - * /, sqrt and the deterministic sine (a local exp2 replaces Math.pow): easings and a timeline hash identically in Node, Chrome 155 and Firefox 158 (added to tools/determinism.js). 23 tests. Not done: colour strings, per-property easing inside one tween, motion along a path, springs.
  • Physics interpolation (engine gap E18). PoseInterpolator in @engine/physics draws bodies smoothly between fixed steps: snapshot() before each world.step, then pose(body, alpha, out) blends from the pose before the step to the pose after it, for World2D and PhysicsWorld alike (rotations the short way round, unit length kept, nothing allocated when out is reused). Read-only, so replays and network games are unaffected. 6 tests, including a replay with and without it that is bit-identical.
  • Navigation meshes and crowd avoidance (engine gap E19). @engine/ai now has NavMesh for open worlds where the grid is the wrong tool. NavMesh.build(vertices, indices, { maxSlope, agentRadius, maxEdge }) keeps the triangles an agent can stand on (facing up, not too steep), joins their corners, links triangles along shared edges, and indexes them in a grid (100,000 triangles build in about 0.15 s, so baking at run time is just building again). findPath runs A* over the triangles (crossing each edge where the straight line toward the goal meets it, which keeps the corridor near the shortest route), pulls the string with the funnel algorithm, moves wall corners away along the way the wall faces until the path clears them by the agent's radius, and cuts corners an agent that wide can walk straight past; partial: true goes as near as possible when there is no route. Also move (walk over the surface, sliding along walls), raycast, isVisible, canWalk (for an agent of a given width), nearest, polyAt/heightAt (told apart by height for bridges), randomPoint, dynamic obstacles (block, blockCircle, unblock, a version that agents watch) and kinds of ground with cost multipliers (setArea, areaCost).
