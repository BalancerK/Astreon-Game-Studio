class InterpolationClock#

class InterpolationClock

Decides which server tick to draw other entities at.

Snapshots arrive "late" by the network latency plus some queueing jitter. For smooth interpolation we render slightly in the past: far enough behind the newest snapshot that the next one has (almost always) arrived, but no further, because every extra tick of delay is visible lag.

Measured per snapshot:

  • lateness m: smoothed (arrival time in ticks - snapshot tick), i.e. the latency floor plus average queueing;
  • jitter d: smoothed mean deviation of lateness (RFC 3550 style);
  • gap: spacing between accepted snapshot ticks (1 normally, larger when packets are lost). The buffer follows a slowly decaying peak of the gap, not its mean, because one lost snapshot must not starve rendering;
  • step detection: if lateness stays far from its estimate for several snapshots (a route change), the estimate jumps to the new level at once instead of crawling there.

Buffer depth = peak gap + k * jitter, clamped. The defaults (k = 4, minimum 2 ticks) came from sweeping the arena network lab (tools/arena-netlab-sweep.js): with k = 3 and a 1.5 tick minimum, a link with only 10 ms of jitter starved 4% of frames; k = 4 with a 2 tick minimum removed that at a cost of ~8 ms. The render clock then slews toward now - m - buffer by speeding up or slowing down at most maxRateAdjust, so a changing target never makes motion visibly jump, and it only snaps when the target moves far away (e.g. a route change).

class Predictor#

class Predictor

Client-side prediction with server reconciliation: applies your own inputs at once with the server's step function, checks them against the server's acknowledged state, and when they disagree adopts the server's state, replays the newer inputs and eases the visible jump away. Draw renderState(alpha).

class RollbackSession

Rollback netcode: every player runs the whole game, unknown remote inputs are guessed, and when a real input differs from its guess the session goes back and simulates forward again within one advance(). Only inputs are sent; checksums find the moment two machines stop agreeing.
