@engine/persist

What outlives a match: a versioned key-value store (memory, files), player profiles with a write-behind cache and migrations, leaderboards, guest accounts and an append-only log.

npm install @engine/persist

Version 0.1.0. The package's own README (packages/persist) explains how the pieces fit together; this page lists every export.

class Profiles#

class Profiles

Player profiles: the data that outlives a match. A profile is open while its player is connected: changes are made in memory and written back in the background, when the player leaves and on shutdown. Old layouts are upgraded as they are read, and a write that finds another server changed the profile is merged (or the conflict is counted) rather than lost.

class FileStore#

class FileStore

Records as JSON files in a folder: <dir>/<namespace>/<two hex digits>/<key>.json, each written to a temporary file and renamed into place, so a crash never leaves half a record. Writes to one record are queued, so version checks are exact inside one server process. Use it for one server (or one server per folder); several servers sharing records need a database behind the same Store contract. list reads folder names: fine for thousands of records, not for millions.

class GuestAccounts#

class GuestAccounts

Players without a sign-up: the first time someone plays they get an id and a secret to keep in the browser; showing the secret later proves it is the same player. Only a hash of the secret is stored. Accounts can later be linked to a login from outside (a platform or social id), which is how a guest keeps their progress when they sign in on another device.
