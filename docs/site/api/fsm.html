@engine/fsm

Hierarchical state machines (events, timers, history, saving) and an animation graph with blend trees and cross-fades.

npm install @engine/fsm

Version 0.1.0. The package's own README (packages/fsm) explains how the pieces fit together; this page lists every export.

class AnimationGraph#

class AnimationGraph

Blends animation clips driven by parameters and triggers: states that play a clip or a 1D blend tree, transitions on parameter conditions, triggers or finished clips, cross-fades and interrupts. update(dt) advances it and sample(...) gives the pose to draw.

class StateMachine#

class StateMachine

A hierarchical state machine: states with enter / update / exit, transitions on events, conditions and timers with priorities, "from any" transitions, nested machines inside states (with history), loop detection and save / load. Can be defined from plain data.

StateMachine.go#

go(ctx, to, { action, history = false, event = null } = {})

Move to another state now. to is relative to this machine: a sibling ("run"), a state inside a sibling ("combat/aiming"), or up through the machines around it ("../dead" from inside "combat").

Advance time, follow transitions that are due, and run the current states' updates (parents first).

StateMachine.send#

Tell the machine something happened. The deepest state that has a transition for it handles it.

Returns boolean — whether a transition was taken

StateMachine.post#

post(event)

Remember an event to be handled at the end of the next update (for code that runs mid-frame).

StateMachine.save#

save()

Where the machine is, as plain data (state path, time in each level, remembered history, memory).

StateMachine.load#

load(data)

Put the machine back where save() found it. Enter / exit functions are not called (the world is restored separately).
