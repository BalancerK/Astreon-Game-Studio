class ClientReplicator#

class ClientReplicator

Everything the server remembers and decides for ONE client's replication.

A client's "view" is the snapshot it was sent: only the entities it is interested in, and (when a bandwidth budget is set) not all of them freshly updated, because far-away, low-priority entities may carry slightly older values. So deltas are computed against the views we actually sent (kept in a per-client history, keyed by tick), not against the world.

Per tick: setVisible (who), buildView (what values, within budget), encode (bytes + history).

Budget: each unsent entity accumulates priority (faster when near), the highest-priority ones get fresh values, and an AIMD controller adjusts how many per tick so the measured bytes/second tracks the budget. The client's own entity and entities it has never seen are always fresh.

class InterestGrid#

class InterestGrid

Interest management: which entities does a given client need to know about? A uniform grid over entity positions, rebuilt once per tick, answers "everything within R of this point" cheaply, so the cost of serving a client depends on how much is near it, not on how big the world is.

Hysteresis stops flicker at the boundary: an entity becomes visible inside enterRadius but only stops being visible outside leaveRadius (> enter).

class ProcessRoom#

class ProcessRoom extends ChannelRoom

A room in its own OS process, connected to the gateway by an IPC channel.

Containment beyond a worker thread: a heap cap (memoryMb) so a leaking or hostile room dies alone (V8 aborts the process, the gateway sees the exit and reports it), a scrubbed environment, optional Node permission-model confinement (confine), and lower scheduling priority if asked. If the gateway dies, rooms exit with it.

class RoomManager#

class RoomManager

Creates, finds and retires rooms, and routes incoming connections to them.

  • Rooms are created on demand (autoCreate) up to maxRooms, each with at most maxPlayers.
  • A connection that arrives while its room is still starting is held (its early packets are buffered and replayed) until the room is ready.
  • Empty rooms are closed after idleCloseMs.
  • A room that crashes disconnects only its own players; the next join to that name starts a fresh room.

RoomHandle#

The gateway-side handle on one room. Three implementations share this interface so a game can choose isolation per deployment without changing room code:

  • ProcessRoom: the room runs in its own OS process. Strongest containment: a crash, a runaway allocation (per-room heap cap), a native fault or a hang kills only that process, and the OS can limit it further.
  • WorkerRoom: the room runs in its own worker thread. Nothing is shared; a slow or crashing room cannot stall or take down the gateway or other rooms, but a native crash or out-of-memory still takes the whole process.
  • InlineRoom: the room runs in this thread (cheapest, no message passing; one room can stall the others).

A room module exports createRoom(options) returning { attach(transport), close?(), stats?(), control?(data) }.
