@engine/matchmaking

Getting players into games: fair queues with parties and widening skill windows, balanced teams, Elo ratings, a room directory with join codes and seat reservations, signed join tokens and an HTTP match service.

npm install @engine/matchmaking

Version 0.1.0. The package's own README (packages/matchmaking) explains how the pieces fit together; this page lists every export.

updateRatings#

function updateRatings(teams, { k, scale = 400, floor = 100 } = {})

New ratings after a match between two or more teams. With more than two teams each pair counts once and a player's change is the average over their opponents, so a four-team free-for-all is fair to everyone. Rating points are zero-sum between equal-sized teams.

Parameters

NameTypeDescription
teamsArray<{players: Array<{id: string, rating: number, games?: number}>, place: number}>place 1 is the winner; equal places are a draw.
o (optional){k?: number | ((player: {games?: number}) => number), scale?: number, floor?: number}k: the most a rating can move in one match (default 32, or 40 for a player's first 10 games and 24 after 100); floor: the lowest rating (default 100).

Returns Map<string, {before: number, after: number, delta: number}> — by player id

class Matchmaker#

class Matchmaker

The matchmaking queue. Players (alone or in parties) enqueue for a mode; tick() turns the queue into matches: similar ratings and even teams first, looser rules the longer someone has waited, a partly filled match after relaxAfterMs, and tickets that waited too long come back as expired. No timers, network or randomness inside: you pass the clock and call tick().

class MatchService#

class MatchService

The matchmaking service: a Matchmaker, a timer that ticks it, and an HTTP handler.

POST /queue { mode, players?: [ids], region?, meta? } -> 201 { ticket } GET /ticket/<id> -> { status: 'waiting' | 'matched' | 'expired' | 'cancelled', ... } (matched: { room, token, team, match }) DELETE /ticket/<id> -> 204 GET /status -> { modes: { duel: { tickets, players, estimatedWaitMs } } }

userOf(req) says who is calling (your login check); a caller may only queue as themselves, and as a party only players canParty allows.
