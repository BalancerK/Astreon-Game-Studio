@engine/transport

Reliable/unreliable channel contract, in-memory network + loss/latency simulator, own RFC 6455 WebSocket server and client.

npm install @engine/transport

Version 0.1.0. The package's own README (packages/transport) explains how the pieces fit together; this page lists every export.

Constants#

CHANNEL#

const CHANNEL

Transport contract. Every adapter (in-memory, WebSocket, WebTransport...) implements Transport for one connection and Listener for a server.

Channels:

  • RELIABLE: ordered and lossless (handshake, spawn/despawn, chat).
  • UNRELIABLE: may be dropped, duplicated or reordered (snapshots, inputs). Payloads must carry their own tick/sequence so stale or duplicate messages can be discarded. A WebSocket adapter maps both channels onto one ordered stream, so a lost packet delays later ones; newer snapshots supersede older ones, so receivers should just drop anything stale.

send copies the bytes (or finishes with them) before returning, so callers may reuse their buffer immediately.

Value: Object.freeze({ RELIABLE: 0, UNRELIABLE: 1 })

class FrameParser#

class FrameParser

Incremental frame parser and message assembler. Feed it socket chunks with push; it calls back with complete binary messages and control frames, and throws WsError on any violation (the caller closes with err.code).

Text frames are rejected (1003): this transport is binary only. Extensions (RSV bits) are never negotiated, so any RSV bit is a violation.
