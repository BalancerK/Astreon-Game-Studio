@engine/render

2D sprites, text (including scalable SDF text) and a 3D mesh renderer with glTF loading: WebGPU -> WebGL2 (-> Canvas2D for 2D).

npm install @engine/render

Version 0.1.0. The package's own README (packages/render) explains how the pieces fit together; this page lists every export.

class Font#

class Font

Text as ordinary sprites. Each glyph is drawn once, in white, into the shared atlas by the browser's own text engine (any installed or web font, emoji, accents, CJK), then drawn like any other sprite and coloured by the tint. So text costs no extra draw call, works identically in all three backends, and sorts with everything else.

Glyphs are rasterised at size * scale pixels and drawn at size world units, so for crisp text pass scale: devicePixelRatio and draw it with a screen-space camera (Camera.setScreenSpace), where one world unit is one CSS pixel. Text in a zoomed world camera gets blurry or blocky; make a Font at the size you need.

Pass sdf: true (or { size, spread }) for scalable text: glyphs are stored as signed distance fields and the shader draws a sharp anti-aliased edge at any size, rotation or camera zoom (stored once at about 48 px, drawn from 8 to several hundred world units). It costs a one-off distance transform per glyph and is a little softer than hinted raster text at small sizes (under about 14 px), so use plain Font for small UI text and sdf for the rest.

Plain Latin, Cyrillic, Greek and CJK text is laid out glyph by glyph (per-glyph advances, no kerning), with \n line breaks and optional word wrap. Text that needs more goes through the layout engine (see textlayout.js) without your doing anything: right-to-left and mixed-direction text is reordered (bidi.js), words in Arabic, Hebrew, Indic and Southeast Asian scripts are shaped by the browser as whole words, and an emoji with its skin tone or a letter with accents is one unit.
