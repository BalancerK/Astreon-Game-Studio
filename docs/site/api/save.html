@engine/save

Save and load: slots, quick and auto saves, checksums and backups, all-or-nothing loads, versioned data with migrations, sections for the scene, physics and state machines, storage in memory, localStorage, IndexedDB, files or over HTTP.

npm install @engine/save

Version 0.1.0. The package's own README (packages/save) explains how the pieces fit together; this page lists every export.

class CloudSync#

class CloudSync

Cloud saves: sync() brings the slots on the device and on the server into step, in both directions, without ever losing a save. Both sides are {get, set, delete, keys} storages, so the server can be HttpStorage (with createSaveHandler on your own server, or anything that speaks the same few requests), a folder, or another device's storage in a test.

For each slot, it compares the two files with a record, kept on the device, of the file both sides held when they last agreed: only the device changed: upload; only the server changed: download; the same on both: nothing; both changed (played offline on two devices): a conflict, settled by strategy. Before a file is replaced on either side the old one is kept as .bak, as SaveGame does, so even a wrong choice can be undone by hand.

createSaveHandler#

function createSaveHandler({ storageFor, userOf, maxBytes = 4_000_000 })

An HTTP handler for saves: GET / lists keys (?prefix=), GET /key, PUT /key, DELETE /key. Keys are checked, bodies are capped, and each file has an ETag (its checksum): a PUT with If-Match that no longer matches is refused with 412, If-None-Match: * only creates. Use it under a path of your server, after your own authentication: userOf(req) returns who the request is for (a directory name), or null to refuse.

SlotInfo#

What CloudSync did, or found, for one slot.

  • same: both sides hold the same save. uploaded / downloaded: the older side (or the side without the slot) was brought up to date. deleted: the slot was deleted on one side and, with deletions, now on the other (from says where it was deleted).
  • conflict: both sides changed since they last agreed and nothing was written (with strategy: 'ask', or a merge that declined): local and remote describe both.
  • resolved: it was a conflict, and the strategy chose (chose says which side, or merged).
  • failed: a side could not be reached or a file was unreadable (error).

Type: {savedAt: number, playtime: number, title: string \| null, sum: string, bytes: number}

SyncResult#

What CloudSync did, or found, for one slot.

  • same: both sides hold the same save. uploaded / downloaded: the older side (or the side without the slot) was brought up to date. deleted: the slot was deleted on one side and, with deletions, now on the other (from says where it was deleted).
  • conflict: both sides changed since they last agreed and nothing was written (with strategy: 'ask', or a merge that declined): local and remote describe both.
  • resolved: it was a conflict, and the strategy chose (chose says which side, or merged).
  • failed: a side could not be reached or a file was unreadable (error).

Type: {slot: string, action: 'same' \| 'uploaded' \| 'downloaded' \| 'deleted' \| 'conflict' \| 'resolved' \| 'failed', from?: 'local' \| 'remote', chose?: 'local' \| 'remote' \| 'merged', local?: SlotInfo, remote?: SlotInfo, error?: string}
