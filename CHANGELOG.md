# Changelog

All packages are released together under one version number. `node tools/release.js bump patch|minor|major` turns "Unreleased" into the next version.

## Unreleased

- Arcade lights now cast **shadows** and can have a strong **core**: list the kinds of thing that block light in `screen.occluders`, and each light's glow is cut by their shadows (`light.shadows: false` opts a light out; `light.core` keeps full strength out to that fraction of the radius). `shadowShapes` is exported. The Lights panel has the matching controls. Files without these fields draw exactly as before.

- Studio: **Play with a friend** panel. Two browsers join with a pair of invitation codes (WebRTC, no server), check they have the same game, and run it in lockstep, trading only held keys. Arcade kit gains `Lockstep` (`packages/arcade/src/netplay.js`) and `me()`/`playerCount()`/`isOnline()`/`isWaiting()`; a game opts in with `export const players = 2` and reads `inputs` (4th argument of `update`).

- **Polish and gap closing, first pass.** `@engine/render`: `filter: 'nearest'` / `setFilter` for pixel art on all three 2D backends; `Font` option `kerning`; `Atlas.clear()` with `Font.reset()` / `BitmapFont.reset()` / `FontStack.reset()` / `RichText.reset()` to recover from a full text atlas; the WebGL2 renderer links programs that lack a scene block, and compiles the sky and water shading only for `createRenderer3D({ water: true })` (it made the main shader slow to compile). `@engine/physics`: `TriWorld.addTriangles` for terrain. The 2D renderer features, text, terrain, water, sky and skeleton pages now also pass in Firefox (`--firefox` on their tools), which exercises the WebGL2 shaders on a second implementation.

- **Browser-to-browser play over WebRTC (engine gap E31).** `@engine/transport`: `listenWebRTC` / `connectWebRTC` (a player's browser hosts, others join: every peer is an ordinary `Transport`, with a truly unreliable second channel), `RtcTransport`, pluggable signalling (`LoopbackSignaling`, `BroadcastSignaling` for tabs of one site, `connectSignalingServer`), `createSignalingServer` (Node; relays handshakes only, lists public rooms, limits and origin allowlist) with `npm run signaling` / `tools/signaling-server.js`, and serverless invitation codes (`createInvitation`, `acceptInvitation`). No STUN or TURN is contacted unless you pass `iceServers`. Tests: 23 in Node with a fake `RTCPeerConnection`, and `tools/webrtc-test.js` with real WebRTC in Chrome and Firefox (3000 ordered messages, a 60 KB message, the unreliable channel, a real signalling server, invitation codes, and the real delta-snapshot replication between a host and a player). Known limits: no host migration, no relay service for players behind strict NATs (bring your own TURN), and hosting a public signalling server is up to you (nothing here is a hosted service; the studio's hosting decision is still open).

- **Terrain, water, decals and a procedural sky (engine gap E7).** `@engine/render`: `Heightmap` (noise, picture or function; sculpt, erode, raycast, slope, collision triangles) and `Terrain` (chunks with four levels of detail and skirts, `splatMap` / `paintSplat`, decals), drawn with the new `list.setTerrain` splat mapping; `createDecal` / `meshTriangles` (a surface clipped to a box, with projected texture coordinates); `createSky`, `sunDirection`, `skyLighting`, `proceduralSkyEnvironment` and `lighting.sky` (a Rayleigh and Mie atmosphere with sun, clouds, stars and a moon, drawn per pixel in WGSL and GLSL from the same model as the CPU `skyRadiance`); `createWaterMesh`, `createWaterStyle`, `waterHeightAt`, `lighting.water` and `list.setWater` (Gerstner-style waves, depth colour, sky reflection, glints, shore froth). Tests: 40 in Node, and `tools/render-terrain-test.js` in Chrome on WebGPU and WebGL2 (the sky matches the model sample for sample; the two backends draw the same water). Known limits: one splat map and four pictures per terrain, no terrain collision shapes in `@engine/physics` (use `toTriangles`), the sky is single scattering with no volumetric clouds, water has no refraction of what is under it (it tints by depth) or shadows, and a water surface is a flat grid at one height (rivers and waterfalls are separate meshes).

- **2D skeletal animation (engine gap E13).** New package `@engine/skeleton2d`: bones with five inherit modes, slots and skins, region and weighted-mesh attachments with deformation, bounding boxes with `hitTest`, one- and two-bone IK, keyframe animations (bone rotate / translate / scale / shear, slot colour and attachment, deform, draw order, IK, events) with linear, stepped and Bezier curves, and `AnimationState` with tracks, crossfades, queues, additive layers, empty animations and listeners. It reads the engine's own JSON format (`parseSkeleton`, documented in `src/loader.js`) and draws with `drawSkeleton`. `@engine/render` gains `MeshBatch2D` and `render({ meshes })` (a triangle pass on WebGPU, WebGL2 and Canvas2D, with additive blending; also in `renderLayers`). Tests: 50 in Node for the package, 3 for the batch, and Chrome checks on all three backends (`tools/render-meshes-test.js`, `tools/skeleton2d-test.js`). Known limits: no clipping attachments, path or transform constraints, bone physics, multiply or screen blends; a third animation started mid-crossfade drops the oldest; meshes are not lit.

- **2D lighting (engine gap E11).** `@engine/render`: `Lighting2D` and `Light2D.point / spot / directional` with `renderer.render({ camera, batch, lighting, occluders })`. Normal maps (`atlas.add(..., { normal })`, `atlas.setNormal`, kept on a twin of each atlas page), up to 64 lights at once, soft shadows for up to 16 point and spot lights from a polar shadow map built on the GPU from an occluder batch, sun shadows, specular, `unlit` sprites. WebGPU and WebGL2 only (Canvas2D draws unlit). `lightPixel`, `shadowRing` and `packLighting` are the CPU reference; `tools/render-lighting-test.js` compares 50 checks per backend with it in Chrome at pixel ratios 1 and 2. Known limits: shadows come from sprite alpha only (no polygon occluders), specular is global (no specular map), no light cookies or per-light layer masks, a light that is not in the first 64 nearest the screen centre is dropped, and a shadow-casting sun costs 96 mask lookups per pixel.

- **2D per-object filters (engine gap E12).** `@engine/render`: `Filter.blur / glow / dropShadow / outline / pixelate / gradientMap / vignette / wave / grayscale / sepia / saturate / hueRotate / brightness / contrast / invert / tint / colorMatrix`, used as `renderer.render({ camera, batch, filters })` on sprites, text or a whole camera, and `renderer.renderLayers({ camera, layers: [{ batch, filters }] })`. One shared plan (`planFilters`) runs as full-screen passes on WebGPU and WebGL2 and on the CPU (`runFilters`) for Canvas2D and as the test reference. Tests: 13 in Node, and `tools/render-filters-test.js` compares every filter on all three backends with the reference at pixel ratios 1 and 2. Known limits: a filter always covers the whole canvas (no area to limit the cost), the filtered group must be its own batch, the Canvas2D path is slow, and the sprite sampler is still linear only.

- **Rich text, right-to-left text, font fallback and bitmap fonts (engine gap E14).** `@engine/render`: `RichText` (BBCode-style markup: bold, italic, underline, strike, colour, size, shadow, outline, links with `linkAt`, inline pictures, font switching, wave / shake / rainbow / fade effects, alignment, typewriter reveal, wrapping), `FontFamily`, `FontStack` (fallback by measured coverage or explicit ranges), `BitmapFont` (BMFont text / XML / JSON with kerning, or a grid sheet; `parseBmfont`), and a paragraph engine under `Font` (`layoutParagraph`, `graphemes`, Unicode bidi in `resolveBidi` / `visualRuns`, browser-shaped Arabic / Hebrew / Thai / Indic words, accent and emoji clusters, East Asian line breaking rules). Tests: 22 in Node plus Chrome checks on all three backends (`tools/render-text-test.js`, bidi checked against Chrome on 6,762 strings). Known limits: no kerning for system-font per-glyph text, no justify or vertical text, bidi classes are approximated by script for rare historic scripts, the atlas never evicts glyphs, and pixel fonts blend slightly at edges when scaled (the sprite sampler is linear).

- **Audio sprites, streaming music, microphone and voice chat (engine gap E24).** `@engine/audio`: `packSounds`, `AudioSprite`, `audio.createSprite` / `playSprite` (regions with their own voice limit, loops inside a region; `play` gained `duration`, `loopStart`, `loopEnd`, `key`); `audio.streamMusic` and `StreamedTrack` (a media element routed through the music bus: starts at once, almost no memory, `pause`, `resume`, `seek`, cross-fades with buffer music, retried after a blocked autoplay); `Microphone` (level, voice activity, mute, devices) and `captureFrames` (audio worklet, resampled 20 ms frames); and voice chat: `VoiceChat` (transport-agnostic: `onPacket` / `receive`; voice detection or push-to-talk; per-speaker jitter buffer, decoder and positioned playback on the voice bus; mute, deafen, volume, speaking events), codecs `opus` (WebCodecs), `adpcm` (plain JS, 8 KB/s) and `pcm16`, the packet format (fuzz-safe decoder), `JitterBuffer` (order, duplicates, late packets, loss cover, adaptive delay, sequence wrap, bursts), `VoiceSender`, `Resampler`, `FrameSlicer`, `VoiceActivity`, `VoiceRouter` (proximity, team, global, party channels, mutes). 16 + 12 unit tests and `tools/audio-voice-test.js` in real Chrome with a fake microphone (worklet capture, ADPCM at 32 dB, Opus at 1.7 KB/s, loopback chats heard on the voice bus, a streamed track that plays, pauses, seeks and ends). Not done: Opus in-band FEC, your own echo cancellation (the browser's is used), recording or transcribing voice.

- **Accessibility in the engine (engine gap E27).** `@engine/ui`: `accessibilityTree(ui)` (plain data: role, name, value and range, checked, selected, disabled, focused, on-screen bounds; labels beside fields name them; only the top modal screen is exposed while one is open), `speak(node)`, and `attachAccessibility(ui)`, a hidden mirror of the UI in the page with real elements and ARIA roles that a screen reader can read and operate (focus moves both ways between the reader and the UI, clicks and keys reach the widgets, live regions for `ui.announce` and for opening a screen, the typing field labelled, only changed attributes written, `ui.reducedMotion` from the system setting); `ui.setTextScale`, `ui.onFocusChange`, `ui.announce`; widget `a11y` options (`label`, `description`, `role`, `hidden`, `live`) and `style.heading`; `contrastRatio`, `luminance`, `auditTheme` (WCAG AA, names every failure) and `highContrastTheme`. The audit found real faults in the engine's own themes, now fixed: the "danger" button text (3.1:1, new `textOnDanger` colour) and the light theme's accent text, danger text and focus ring. `@engine/input`: pen bindings (`penPressure`, `penTilt`, `penContact`, `penBarrel`, `penEraser`; `createInput({ pen: true })`, `attachPen`, `InputCore.penUpdate`), `StrokeRecorder` / `penWidth` / `attachPenStrokes` for drawing, and `GestureRecognizer` / `attachGestures` (tap, double tap, long press, swipe, one- and two-finger pan, pinch, rotate). 9 input tests, 12 ui tests and `tools/ui-a11y-test.js` (14 checks in real Chrome with `attachDom`: roles, names, values, focus both ways, keys on a slider and a switch, activation, typing, announcements, teardown). Not done: describing a canvas game scene to a screen reader beyond the UI (use `ui.announce`), right-to-left widget layout, palm rejection, handwriting recognition.

- **Replays, spectating and cloud saves (engine gap E32).** New package `@engine/replay`: `ReplayRecorder` / `ReplayPlayer` record a match as the network's own quantised delta snapshots with a full one every `keyframeEvery` ticks (seek anywhere, any speed, pause, loop, events tied to ticks, the next frame always decoded so `history.around(tickAt)` interpolates; a file can be written as it goes with `onChunk` and one cut short by a crash still plays; the schema hash and a format version are checked; 5 minutes of 40 entities is 0.8 to 3.4 MB depending on how much moves), `InputRecorder` / `InputPlayer` keep only the inputs of a deterministic game (run-length encoded, a few KB, checkpoints so a seek costs at most `checkpointEvery` ticks, state hashes so a replay that drifts raises `ReplayDesyncError` at the tick it happened), and `SpectatorFeed` / `SnapshotReceiver` broadcast the full world a fixed delay behind the players with the bytes shared among spectators that start from the same snapshot (the receiver asks for a full snapshot when it lacks a baseline, ignores late and repeated packets and survives garbage). `@engine/save` gains `CloudSync`: brings the slots on the device and on a server (`HttpStorage` + `createSaveHandler`, or any storage) into step in both directions from a record of what both sides held when they last agreed, so a change on both sides is a conflict and never an overwrite (`strategy`: `newest`, `local`, `remote`, `ask` + `resolve`, or a function that can return a merged save), keeps the replaced file as `.bak`, copies the load-screen header, optionally carries deletions, reports a damaged file or an unreachable server per slot, and a write that races another device is refused by the server's `If-Match` and reported. 11 + 8 replay tests and 8 cloud-sync tests (including a real HTTP server). Not done: server-side spectator cameras, taking over a replay as a live player, a hosted save service (the server side, `createSaveHandler`, existed; where to host it is the S8 decision).

- **Ragdolls and raycast vehicles (engine gap E17).** `@engine/physics`: `ConeJoint` (a ball joint with a swing limit, saved and restored with the world), `world.ignoreCollision(a, b)` / `allowCollision`, `Ragdoll` + `humanoidRagdollSpec` (13 capsules with cone joints at shoulders, hips, neck and ankles and one-way hinges at elbows and knees; `setBone`, `setLinearVelocity`, `applyImpulse`, `centerOfMass`, `addTo` / `removeFrom`), and `RaycastVehicle` (spring-and-damper ray wheels, a friction circle per tyre, engine, brakes, hand brake, steering, anti-roll bars, `wheelMatrix` for drawing). `@engine/render`: `poseToRagdoll`, `poseFromRagdoll` and `ragdollSpecFromSkeleton` connect a ragdoll to a `Skeleton`. 17 physics tests, 5 pose tests, and two new cross-engine hash suites (`rigid.ragdoll`, `rigid.vehicle`) that Node, Chrome and Firefox agree on bit for bit. **Fixed:** a force added with `applyForce` or `applyTorque` was cleared after the first substep, so with the default 2 substeps it acted for half the step it was applied for; forces now last the whole step, as documented (no existing hash or test changed). Not done: ragdoll twist limits and getting up again, gears and tyre slip curves, soft bodies and cloth (priority C).

- **Inverse kinematics and animation retargeting (engine gap E21).** `solveTwoBone` (exact arm and leg solution with a pole point, `endRotation`, `weight`; stretches straight at a target out of reach), `solveChain` (FABRIK for tails, spines, tentacles; bone lengths kept, root fixed), `aimJoint` (turn a joint's axis to a point, with an angle `limit` and `weight`), and retargeting: `retargetClip(clip, from, to)` / `retargetPose` copy the change-from-rest of each joint in world space onto the destination's own rest orientation (A-pose to T-pose, different bone axes), scale the hips' movement by hip height, and `autoMapJoints` / `humanoidKey` pair joints by meaning across Mixamo, Unity, Blender, Biped and VRM names (with `overrides`). 15 unit tests (targets reached to 1e-4, bone lengths kept, pole side, limbs under rotated parents and a rotated root matrix, weights, chains in longer skeletons, aim limits, name matching across schemes, retargeting between a Mixamo T-pose rig and a taller A-pose rig, clips). Not done: joint limits and twist, IK against the physics world, non-humanoid retargeting without a map.

- **Spot lights, area lights and shadows from point and spot lights (engine gap E3).** The entries of `lighting.pointLights` can now be spot lights (`direction`, `angle`, `penumbra`) and rectangular area lights (`type: 'area'`, `width`, `height`, `direction`, `right`; one-sided; shaded with the nearest point of the panel for diffuse light and the point nearest the mirror direction for highlights, scaled by the solid angle it fills), and any point or spot light can cast shadows with `castShadow: true`: a spot light renders one perspective depth map and a point light six (a cube), into their own array of up to 12 layers (`render({ localShadows: { size, layers, bias, strength } | false })`), given to the nearest lights when more ask than fit. The shadow lookup moves the surface toward the light and off itself by about a texel before a 3x3 comparison, so it needs no per-light bias tuning. `DrawList3D.setCamera(camera, { lights })` keeps off-screen casters inside a shadow-casting light's reach. Both renderers share one light evaluation (`localLight`) in WGSL and GLSL, used by the simple and the physically based paths; point lights without the new fields shade exactly as before. The scene uniform block grew (the new per-light data and the shadow matrices sit after the cascade block, so earlier offsets did not move); the four copies of the block in the WebGL2 shaders are now one. 9 unit tests and `tools/render-lights-test.js` (17 checks on each of WebGPU and WebGL2: cone, soft edge, aiming, one-sided and size-scaled panels, symmetric panel light, point-light shadows in three cube faces, spot-light shadows on simple and physically based floors, a caster behind the camera, the layer budget, and WebGPU against WebGL2 on five scenes within 1.5/255). Not done: penumbra shadows that widen with distance, shadows from area lights, cookies and IES profiles, exact (LTC) area lighting, tube and sphere shapes.

- **Ambient occlusion, depth of field and FXAA (engine gap E4).** Three new `post` options, each off unless given and free when off, on WebGPU and WebGL2: `ao` (screen-space ambient occlusion from the depth buffer, with normals rebuilt from depth, a rotated hemisphere kernel, and a depth-aware separable blur; `radius`, `intensity`, `power`, `bias`, `samples`, `scale` for half-resolution), `dof` (thin-lens depth of field, `focus`, `range`, `aperture`, `maxBlur`, `taps`, with a gather that keeps a sharp foreground from bleeding into a blurred background) and `fxaa` (one pass on the finished picture, so it also works with `antialias: false`). Both renderers now keep the scene's depth as a texture when a depth effect is on (WebGL2: a depth texture resolved from the multisampled one; WebGPU: the depth texture is stored and read as a multisampled depth texture); an orthographic camera skips the depth effects. `circleOfConfusion(distance, dof)` is exported (the shader's own blur size, for autofocus). 7 unit tests and `tools/render-postfx-test.js` (WebGPU and WebGL2, each with and without multisampling: the floor at a cube's foot darkens and open floor, the top and the sky do not; half resolution works; stripes at the focus keep their sharpness while nearer and farther ones blur; `range` keeps a band sharp; FXAA adds in-between pixels to a staircase edge and leaves flat areas alone; everything at once draws; turning the effects off restores the plain picture exactly). Not done: temporal anti-aliasing (needs motion vectors), screen-space reflections, occlusion from things outside the screen, a near blur that spreads over a sharp background.

- **Drawing less (engine gap E5): levels of detail, occlusion culling and static merging.** *Levels of detail:* `simplifyMesh(mesh, { ratio | cellSize, keepEdges })` makes a coarser copy by vertex clustering (linear time, works on skinned meshes, a 100,000-triangle sphere to 10% in about 50 ms); `createLod({ mesh, ratios, screens, cullBelow })` (or your own `levels`) bundles versions with the on-screen size at which each takes over, and `DrawList3D.addLod` / `addSkinnedLod` pick the level for the camera each frame (and draw nothing below `cullBelow`; `list.lodBias` shifts every choice). *Occlusion culling:* `OcclusionBuffer` is a 128 x 72 depth image drawn on the CPU from your walls and buildings (`addBox`, `addMesh`), and `DrawList3D.setOcclusion` drops instances whose bounding sphere is behind it (20 boxes fill in 0.09 ms, 2,000 tests cost 0.14 ms); no GPU queries, so no latency or flicker, and the same on every backend. It only drops what is certainly hidden (checked against ray casts over thousands of random scenes), and keeps everything when shadows are on, since a hidden thing can still throw a shadow into view. *Merging:* `StaticBatcher` collects placed pieces and `build()` merges the ones with the same colour and texture in the same grid cell into single world-space meshes (normals through the inverse transpose, mirrored pieces re-wound), drawn with `DrawList3D.addBatch`: 5,000 boxes become 32 batches in 9 ms. 12 unit tests and `tools/render-drawless-test.js` (WebGPU and WebGL2: merged batches look like the pieces drawn one by one, the LOD draws exactly what the chosen level draws, and the occluded scene is pixel-identical to the unculled one while dropping the hidden instances). Not done: switching levels without a pop (no cross-fade or hysteresis), GPU occlusion queries, occluders that cross the near plane, merging pieces with different colours (colour is per batch, not per vertex), and automatic occluder detection.

- **Video as a texture (engine gap E15).** `VideoTexture(set, source)` keeps one layer of a 3D `TextureSet` showing the current frame of a `<video>`, canvas, `ImageBitmap` or `VideoFrame`; `VideoSprite(atlas, source, { name, width, height })` does the same for a rectangle of the 2D `Atlas`. Call `update()` once per frame: it asks the video whether it has a new picture (`requestVideoFrameCallback`; an older browser is judged by the clock) and does nothing while it is paused, otherwise draws it with `cover` / `contain` / `stretch` fitting, rebuilds the mip levels in place and lets the renderer upload just that layer. New underneath: `TextureSet.update(layer, image)` (replace a layer's pixels without allocating; each layer has its own `version`, which both 3D renderers now check) and `Atlas.redraw(name, draw)`. 7 unit tests, and `tools/render-video-test.js` plays a real `<video>` (a canvas stream going red, green, blue) as a 3D texture on WebGPU and WebGL2 and as a sprite on WebGPU, WebGL2 and Canvas2D, checking the colours come round, that only new frames are uploaded and that a paused video costs nothing. Not done: sound or playback control (the element is yours), video files decoded without an element (WebCodecs), playing a video straight into a compressed texture set, and a partial upload for 2D (the whole atlas page is uploaded again, so give video a small atlas of its own).

- **Engine-level localisation (engine gap E29): the new `@engine/i18n` package.** `Localizer` holds a table per language and gives `t(key, params)`, `tn(key, count)` (the right plural form for any language: CLDR names such as `one` / `few` / `many` from the platform's own `Intl.PluralRules`, or a gettext list with the `Plural-Forms` rule), `tc(context, key)` and `tcn` (the same word used two ways). It reads gettext **`.po` files** (`msgctxt`, `msgid_plural`, `msgstr[n]`, continued lines, escapes, fuzzy, the `Plural-Forms` header, whose expression is parsed by a small safe parser and never evaluated) and **CSV sheets** (`key`, `context`, a column per language, `thing.one` / `thing.other` rows; tables made for the arcade kit work unchanged). Falls back from `pt-BR` to `pt` to the default language, reports each missing word once (`onMissing`), lists what is untranslated (`missing(lang)`), writes a translator's sheet (`toCsv()`), formats `{n:number}` and `{names:list}` for the language, and **pseudo-localises** (accents, a third longer, bracketed, `{places}` kept) to find broken layouts. 18 tests, including the real plural rules of English, French, Russian, Polish, Arabic and Japanese. Not done: ICU select / nested messages, ordinals, date and currency formats, writing `.po` back.

- **Tweens and timelines (engine gap E22): the new `@engine/tween` package.** `Tween` moves numbers, lists of numbers (colours, vectors, typed arrays, in place), dotted paths and relative values (`'+=50'`) on any object with a delay, repeats, yoyo, `timeScale` and start / update / repeat / complete callbacks; `Timeline` lays tweens, calls and other timelines on one clock with GSAP-style places (`'-=0.2'`, `'<'`, labels, `'open+=1'`); `Tweens` plays them and drops the finished. 31 easings (`sine`, `quad`, `cubic`, `quart`, `quint`, `expo`, `circ`, `back`, `elastic`, `bounce`, each in / out / in-out) plus your own function, a CSS-style cubic bezier and `steps(n)`. Everything is a function of its clock, so `seek(t)` and `progress` put every property exactly where it belongs (forwards or back, silently), which makes cutscenes scrubbable and replays exact. Built from `+ - * /`, `sqrt` and the deterministic sine (a local `exp2` replaces `Math.pow`): easings and a timeline hash identically in Node, Chrome 155 and Firefox 158 (added to `tools/determinism.js`). 23 tests. Not done: colour strings, per-property easing inside one tween, motion along a path, springs.

- **Physics interpolation (engine gap E18).** `PoseInterpolator` in `@engine/physics` draws bodies smoothly between fixed steps: `snapshot()` before each `world.step`, then `pose(body, alpha, out)` blends from the pose before the step to the pose after it, for `World2D` and `PhysicsWorld` alike (rotations the short way round, unit length kept, nothing allocated when `out` is reused). Read-only, so replays and network games are unaffected. 6 tests, including a replay with and without it that is bit-identical.

- **Navigation meshes and crowd avoidance (engine gap E19).** `@engine/ai` now has `NavMesh` for open worlds where the grid is the wrong tool. `NavMesh.build(vertices, indices, { maxSlope, agentRadius, maxEdge })` keeps the triangles an agent can stand on (facing up, not too steep), joins their corners, links triangles along shared edges, and indexes them in a grid (100,000 triangles build in about 0.15 s, so baking at run time is just building again). `findPath` runs A* over the triangles (crossing each edge where the straight line toward the goal meets it, which keeps the corridor near the shortest route), pulls the string with the funnel algorithm, moves wall corners away along the way the wall faces until the path clears them by the agent's radius, and cuts corners an agent that wide can walk straight past; `partial: true` goes as near as possible when there is no route. Also `move` (walk over the surface, sliding along walls), `raycast`, `isVisible`, `canWalk` (for an agent of a given width), `nearest`, `polyAt`/`heightAt` (told apart by height for bridges), `randomPoint`, **dynamic obstacles** (`block`, `blockCircle`, `unblock`, a `version` that agents watch) and **kinds of ground** with cost multipliers (`setArea`, `areaCost`). `Crowd` walks many agents over it: each has its own path, goal, speed and acceleration limits; each step an agent samples 38 velocities and takes the one closest to its wish that avoids collisions for the next 2.5 s (passing on the right so head-on agents choose opposite sides), is pushed out of anyone it overlaps, stays on the mesh, re-plans by itself when an obstacle changes the mesh, waits as `blocked` when the way is shut, and stops short when its goal is crowded. 12 agents crossing a circle through one point, two groups in a corridor, ten agents sent to one goal around a block, 200 agents (a few ms a step), obstacles added and removed under walking agents, and bit-identical reruns are all in the tests (56 in the package). Deterministic like the rest of the package (the shared-math check covers it; `Math.hypot` is replaced by a square root). The mesh paths, ray casts, an obstacle added and removed, and a 20-agent crowd crossing a field with a wall (an obstacle appearing mid-run) are in the cross-engine determinism suite: Node, Chrome 155 and Firefox 158 produce bit-identical results (`ai.navmesh`, `ai.crowd`). Not done: avoiding moving obstacles the mesh does not know of, and off-mesh links.
- **Morph targets, animation events and root motion (engine gap E20).** *Morph targets (blend shapes):* `MorphTargets(mesh, targets)` gives a mesh of your own whose shape is `base + sum(weight * offset)` (positions and normals), with `set(name, weight)`, `setWeights`, `approach` (ease toward a goal) and `update()` (rebuilds only when a weight changed). Both renderers upload the new vertices when the mesh's `version` goes up, for plain and skinned meshes alike (the shape changes first, then the skeleton moves it). The glTF loader now reads targets, their names, starting weights (node weights win), animations of `weights` (`model.morphClips`, `MorphClip.sample`), and **sparse accessors** (which also hold most real morph targets and used to throw); `createGltfMorph(instance)` makes a controller and `addGltfToDrawList` takes a map of meshes to draw in place of the instances' own, so each character has its own face. *Animation events:* `clip.addEvent(time, name, data)` and `animator.onEvent(name, data, clip)` fire once each as playback passes them, in order, on every lap of a loop and however big the step (an event at time 0 starts each lap). *Root motion:* `new Animator(skeleton, { rootMotion: { joint, axes } })` takes the root's movement out of the pose so feet do not slide, and reports it as `animator.motion`; laps of a loop and steps longer than a lap add up exactly. 12 unit tests (including a glTF with a sparse target, node weights and a weights animation), and `tools/render-morph-test.js` checks on WebGPU and WebGL2, for plain and skinned meshes, that a changed weight changes what is drawn, half way is half as far, and back to zero shrinks back. Not done: morph targets on the GPU (the cost is CPU, vertices times active targets, per change), tangent offsets, events from glTF files (glTF has no event track), rotation in root motion, and events from the clip being faded out.
- **Bus effects, ducking and occlusion (engine gap E23).** `@engine/audio` buses can now carry effects. `engine.addEffect(bus, effect)` puts a `lowpass`, `highpass`, `bandpass`, `filter` (notch, shelves, peaking), `reverb`, `echo` or `compressor` on any bus, master included; effects run in the order added, and the handle changes settings while the sound plays (`set({ frequency: 300 }, 0.5)` glides), bypasses (`enabled = false`) or removes it. The reverb is a convolution with a room made in code from a seed (`reverbImpulse`: decaying noise, 60 dB down over `seconds`, highs dying first, left and right different), so it is the same on every machine and needs no files. **Ducking:** `addDuck({ target: 'music', trigger: 'voice', amount, attack, hold, release })` turns music down while anyone speaks, and back after; rules combine by the quietest. **Occlusion:** `play(sound, { occlusion })` and `voice.setOcclusion(amount, fade)` muffle a voice as if a wall stood between it and the listener (a low-pass and a drop in loudness; the game decides how much wall, for example from a physics ray cast). Every bus now runs through an effects chain and a ducking gain on its way to master. 7 new unit tests against the stand-in Web Audio context, and `tools/audio-effects-test.js`, which renders real audio in headless Chrome and measures it (14 checks: filters cut and pass the right frequencies, reverb tails fade 60 dB, echoes land at 0.3 s and 0.6 s, ducking is exactly -12 dB for a 0.25 duck and recovers, a wall takes 39 dB off a 3 kHz voice). - **2D rigid bodies (engine gap E16).** `@engine/physics` now has a 2D rigid-body world beside the 3D one: `World2D`, `Body2D`, `circleShape`, `boxShape`, `polygonShape` (convex, up to 16 points), and the joints `RevoluteJoint2D` (pin or hinge, optional motor), `WeldJoint2D` and `DistanceJoint2D` (rod or spring). Bodies stack, tumble, slide and bounce with friction and restitution, can be dynamic, kinematic (platforms that carry things) or static, can be sensors, have collision groups and masks, and sleep when at rest. The solver is sequential impulses with warm starting (contacts keep their impulses between steps, matched by the edges that made them) and speculative contacts for fast pairs, so a ball at 150 m/s stops at a thin wall and nothing sinks in and pops back out. `raycast`, `queryPoint`, `queryAabb`, begin/end/trigger events, and `getState()`/`setState()` for saves and rollback (a replay from a saved state is bit for bit the same). Not done: joint limits, prismatic and pulley joints, compound shapes on one body, and exact continuous collision between two fast dynamic bodies.
- **A tile-map renderer for big levels (engine gap E10).** `@engine/render` now has `TileMap`, `TileLayer`, `TileSet` and `drawTileMap(batch, map, camera, { time, key })`. A layer keeps its tiles in chunks of 16 x 16 (made as you write to them, so a layer can reach into negative coordinates and be as big as you like); each chunk's sprites are built once and kept, and a frame copies only the chunks the camera sees into the sprite batch (`SpriteBatch.pushBlock`, new), so a map of 1.8 million tiles costs the same to draw as a screenful. Changing a tile (`layer.set`, `fill`, `setData`) rebuilds only its own chunk. Tiles can **animate** (`tileset.animate(id, [{ id, ms }, ...])`, chosen from the time you pass, so a paused game freezes them) and carry **Tiled's flip flags** (`FLIP_H`, `FLIP_V`, `FLIP_D`, drawn as a quarter-turn and a mirror; a test checks every corner of all eight combinations). Layers have an offset, a **parallax** factor, an opacity, a tint, visibility and their own sort key (`key + layer number`, so a map's layers sit among your sprites). Tiles taller than the grid stand on their cell. **`tileMapFromTiled(json, { sheet })`** loads a Tiled JSON map: orthogonal, finite or infinite (chunks), CSV or base64 data, groups, embedded tilesets with animations, offsets, parallax, opacity, tint; object and image layers are named in `warnings` and skipped, and zlib/gzip/zstd tile data and external `.tsx` tilesets are refused with a message saying what to change in Tiled. `sprite batches` now accept a **negative width as a mirror** on all three 2D renderers (the canvas renderer needed a fix for it). 12 unit tests, and `tools/render-tilemap-test.js` checks, on WebGPU, WebGL2 and canvas, all eight flip combinations (32 pixels), animation, a 1.8-million-tile layer, and live edits. - **Smaller downloads: compressed models and textures (engine gap E6, the part that needs no WebAssembly).** `parseGltf` now reads **`EXT_meshopt_compression`** (what `gltfpack` writes: vertices usually a quarter to a fifth of the size) and **`KHR_mesh_quantization`** (positions, normals and coordinates stored as 8 or 16-bit numbers). The meshopt decoder (`packages/render/src/meshopt.js`, also exported: `decodeVertexBuffer`, `decodeIndexBuffer`, `decodeIndexSequence`, `applyMeshoptFilter`, `decodeMeshoptBufferView`) is a plain JavaScript port of the reference decoder (MIT, see NOTICE): both versions of the vertex format, triangle and index-sequence coding, and the octahedral, quaternion, exponential and colour filters, rounding in 32-bit floats as the reference does. It is checked byte for byte against 26 cases the real encoder wrote (`packages/render/test/fixtures/meshopt.json`: several blocks, every stride, all four filters) and by loading a whole compressed, quantised GLB. **`parseKtx2`** reads KTX2 texture files (RGBA8, and BC1, BC3, BC7, ETC2 and ASTC 4x4 already compressed for the graphics card, with zlib supercompression undone), and a `TextureSet` can now be made with `{ format: 'bc7' }` (or bc1, bc3, etc2, astc4x4) and filled with `set.addKtx2(ktx)`: both renderers keep such a set compressed on the card (a quarter to an eighth of the memory; WebGPU asks for the compression features when the card has them, WebGL2 uses the extensions) and say clearly if a card cannot read the format. `tools/render-compressed-test.js` draws BC1 and BC3 pictures on both backends and checks they show the same sixteen colours as the same picture in plain pixels. **Not read, and refused with a message saying why:** Draco (`KHR_draco_mesh_compression`), Basis Universal textures (ETC1S/UASTC, which `basisu` and `toktx --bcmp` write) and Zstandard supercompression: all three need a WebAssembly decoder, which the zero-dependency rule rules out. Compressed layers must be exactly the set's size with every mip level (they cannot be resized or have levels made), and BC7, ETC2 and ASTC were checked only for reading the file and choosing the right card format, since this machine's browser test has BC1 and BC3 pictures only.

- **Environment lighting and a sky (engine gap E2).** `@engine/render` can now light physically based surfaces with the light that comes from all around, and draw it as the sky. An `Environment` is a small cube of colours made from a few colours and a sun (`skyEnvironment`), from a panorama picture (`environmentFromImage`, `loadEnvironment`: PNG and JPEG are read as sRGB, a Radiance `.hdr` file is read with `parseHdr` and keeps a bright sun bright), or as one colour all round. Making one takes a few tens of milliseconds and is deterministic: the cube becomes nine spherical-harmonic colours (the soft diffuse light facing any direction) and a prefiltered chain of blurrier cubes, one per step of roughness, found by GGX importance sampling from a pyramid of the cube so a sun never leaves speckles. `renderer.setEnvironment(env)` gives it to the renderer (both WebGPU and WebGL2, as half-float cube textures); surfaces with a material are lit by it and reflect it, so a polished metal shows the sky and a rough stone is lit softly from where the light really is, and the environment is drawn behind everything as the sky (before the scene, so blended surfaces blend over it). Each frame's `lighting.environment = { intensity, rotation, sky, skyBlur }` turns it about the vertical axis, dims it, hides the sky while keeping the lighting, or blurs the sky; `false` turns it all off. Surfaces without a material keep the plain ambient colours, and `ambientFromEnvironment(env)` gives plain colours that roughly match. `environmentIrradiance`, `sampleEnvironment` and `pbrAmbientEnvironment` are the same maths on the CPU. 13 unit tests and `tools/render-env-test.js` (14 checks per backend: a white environment, a sky with a sun reflected in five metals from mirror to chalk, the sky pixel by pixel, the six cube faces, rotation, intensity, blur, sky and environment off, and untouched simple lighting; all within the CPU model, and the two backends draw the same image). Fog does not touch the sky, and the studio has no environment picker yet.
- **Physically based materials and the full glTF material set (engine gap E1).** `@engine/render` can now light a surface the way glTF describes one. A `MaterialSet` (up to 127 materials, handed to the renderer with `renderer.setMaterials`) holds, for each, a base colour and picture, `metallic` and `roughness` with an optional metallic-roughness picture, a **normal map**, an **occlusion** picture, an **emissive** colour and picture, an alpha cut-off, `uvScale` and an opaque flag; `list.setSurface(id)` makes the next instances use one (0 is the simple lighting, and both kinds share a scene; skinned meshes too). The shading is Cook-Torrance (GGX, Smith height-correlated visibility, Schlick fresnel) with Lambert diffuse, lit by the sun and its shadows and by up to 32 point lights, plus the sky and ground ambient light seen directly and reflected (Karis' analytic approximation, so a metal is not black), fog, and emission. Normal mapping needs no tangents in the mesh: the shader builds the frame from how the texture coordinates change across the screen. Pictures are read as sRGB where glTF says so, lighting is done in linear light, and the result is converted back so materials sit beside the simple lighting. It works on both WebGPU and WebGL2 and the two draw the same picture. The glTF loader now reads every part of a material (the five pictures, factors, `OPAQUE`/`MASK`/`BLEND`, `KHR_materials_emissive_strength`) instead of ignoring all but the base colour; `loadGltfTextures` decodes all the pictures, `loadGltfMaterials` makes the materials, and `addGltfToDrawList(..., layers, materialIds)` draws with them; a call without the last argument draws as before. A second set of texture coordinates, texture transforms, double-sided surfaces and sorting of blended surfaces are reported in `warnings`. `pbrLight` and `pbrAmbient` are the shading maths on the CPU. 14 unit tests and `tools/render-pbr-test.js` (11 checks per backend: about 40 pixels agree with the CPU model to within 1/255 on both backends, across metal and roughness, every kind of picture, cut-outs, point lights and fog, a skinned mesh, changing a material live, and a real glTF with embedded PNGs; the two backends agree exactly). The studio has no material editor yet.
- **Reusable client prediction and rollback netcode (engine gap E30).** `@engine/client` now has two classes any game can use. `Predictor` is client-side prediction with server reconciliation: give it the same step function the server runs, record each input as it is pressed, give it the server's acknowledged state on every snapshot, and draw `renderState(alpha)`. A correct guess changes nothing; a wrong one adopts the server's state, replays the newer inputs and eases the visible jump away. It is checked against the arena's own predictor on the arena's real movement and walls (same positions to within 1e-9 on every tick, with pushes and snaps). `RollbackSession` is rollback netcode for peer-to-peer or lockstep-style games: every player runs the whole game, unknown remote inputs are guessed, and when the truth differs the session goes back and simulates forward again within one `advance()`. It has input delay, a limit on how far ahead it may run (it waits instead), forgets old frames, and finds a desync at the frame it happened with checksums. Tests simulate two machines with even and uneven delays and check every confirmed frame against the same game run on one machine. 12 + 12 unit tests and 3 equivalence tests. The arena example is unchanged.

- `RoomManager` passes `roomName` to rooms; `serve()` in `@engine/build` takes a `handle` hook.

- **New `matchmaking` package:** queues that make fair matches (parties, widening skill windows, regions, partly filled matches), balanced teams, Elo ratings, a room directory with join codes and seat reservations, signed join tokens (`JoinTokens`) and an HTTP match service (`MatchService`).

- **Load test:** `npm run loadtest` runs hundreds of real WebSocket clients (in bot threads) against the arena server and reports join times, snapshot smoothness, bandwidth and tick times; it runs at low priority and asks for `--force` above 300 players.
- **API reference:** `docs/api` now also covers each package's Node entry (`src/node.js`).

## 0.1.0 — 2026-10-12

The first packaged release: 23 packages, each installable on its own.

- **Foundations:** fixed-timestep loop and typed-array ECS (`core`), deterministic maths (`math`), binary delta protocol (`protocol`), WebSocket transport and simulated networks (`transport`), authoritative server pieces (`server`, `client`), debug overlay (`debug`), safe mods (`mods`).
- **Rendering and feel:** 2D sprites and text, a 3D renderer on WebGPU and WebGL2 with glTF, shadows, post-processing and particles (`render`, `particles`); sound (`audio`); input for keyboard, mouse, gamepad and touch (`input`); menus and HUDs (`ui`).
- **Gameplay systems:** rigid-body physics with joints and sleeping and 3D character movement (`physics`); navigation, pathfinding, behaviour trees and perception (`ai`); prefabs (`prefab`); state machines and animation graphs (`fsm`); save and load with migrations (`save`).
- **Content pipeline:** asset manager with hot reload (`assets`); scene files (`scene`); production build and dev server (`build`); a browser scene editor with gizmos, inspector and Play (`editor`).
- **Getting started:** `npx create-game` with a 2D and a 3D template (`create-game`); `tools/release.js` for versions, packing and installing the tarballs.
