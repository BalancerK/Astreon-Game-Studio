# Arena 3D

A first-person multiplayer shooter built on the engine's 3D stack: an authoritative Node server, a browser client (WebGPU, WebGL2 fallback), client prediction of your own movement and shots, lag-compensated hitscan, interest management and mods.

```
npm run arena3d                       # http://127.0.0.1:8081/
node examples/arena3d/server/main.js --mods examples/arena3d/mods   # with the sample mods
```
Open the page in two windows to play against yourself. `?room=alpha` joins (or creates) the room "alpha" (default "lobby"; names a-z 0-9 _ -); `/rooms` lists them. Each room is its own world in its own worker thread (`--mode process` for OS processes), so one cannot stall or crash another. Click to capture the mouse; WASD move, Shift run, Space jump, hold the left button to fire. Escape (or the Menu button, or Start on a gamepad) opens the pause menu: settings (volumes, key rebinding, interface size) and a room browser. F3 (or `?debug=1`) shows the netcode numbers, `?renderer=webgl2` forces a backend, `?shadows=0` turns the sun's shadows off, `?touch=1` shows the on-screen touch controls (they appear by themselves on touch screens; a gamepad works as soon as you press a button on it), `?audio=0` turns the sound off (M mutes, N mutes the music; sound starts at your first click or key press), `?textures=0` shows plain colours, `?predict=0` / `?predictshots=0` turn prediction off to see what it hides.

## How it fits together
| Folder | What |
|---|---|
| `shared/` | Code both sides run, deterministic (checked by `tools/check-shared-math.js` and by hashes in Node, Chrome and Firefox): the level (`level.js`: one description builds collision triangles and what is drawn), the replicated schema and the movement step (`game.js`), the shot geometry (`shot.js`), rules and their ranges (`rules.js`), events. |
| `server/` | `gateway.js` + `room.js`: one port serves the page, `/rooms` and `/ws/<room>`, and routes each socket into a room. `arena3d-server.js` (one room): 60 Hz fixed tick, `CharacterController` bodies, per-client input queues with pacing (`input-queue.js`), delta snapshots filtered by horizontal distance, lag compensation (`weapon.js`), mod commands. `main.js` serves the page and the WebSocket on one port. |
| `client/` | `net.js`: handshake, snapshots, inputs, prediction, shot prediction, mod download and verification (no DOM, so tests and bots use it). `predict.js`: reconciliation of a whole character (position, vertical speed, grounded). `interp.js`: other players at the render tick. `main.js`: the page. |
| `client/character.js`, `client/locomotion.js` | The player model, built in code: a 13-joint skeleton, three skinned meshes (clothes tinted by the player's colour, skin, dark details) and idle / walk / run / airborne clips. `CharacterRig` poses one player each frame from what the network says: speed measured from their movement, idle-walk-run blended by speed, the legs turned toward the direction of travel (strafing and backing up look right while the torso keeps facing the aim), the head following pitch, an airborne pose from the replicated grounded flag, and the lowest foot planted on the floor. |
| (client look) | The level is textured with four tileable textures made in code at startup (grass, brick, concrete, metal plates; no image files), projected from the world so every box and ramp is covered without texture coordinates. |
| (client input) | Played through `@engine/input` actions, so one game runs on keyboard and mouse, a gamepad (left stick moves, right stick looks, A jumps, the trigger fires, L3 runs) or a touch screen (floating stick, drag to look, FIRE / JUMP / RUN buttons). Half a stick push is half speed. Saved bindings are read from `localStorage` (`arena3d.bindings`). |
| `server/bots.js` | The bots' minds, from `@engine/ai`: a navigation grid of the level, sight and memory, a behaviour tree (retreat, engage, investigate, patrol), path searches spread over ticks, shots judged like a player's. `--bots N` sets how many; `botAi: false` gives the old random wandering. |
| `client/menus.js` | The menus, built from `@engine/ui` on the HUD canvas: pause menu, settings (sound sliders, rebinding of jump / run / fire for keyboard and gamepad, interface size, debug overlay; saved in `localStorage` as `arena3d.settings` and `arena3d.bindings`) and a room browser fed by `/rooms`. While a menu is open the input layer switches to a blocking `menu` context, so the game does not hear the keys. |
| `client/effects.js`, `surface.js` | The arena's particles (`@engine/particles`): muzzle flashes on other players' guns, a faint glow along each bullet, sparks, dust and a flat bullet hole laid on the surface the shot hit (`surface.js` finds the surface's normal in the level), a red burst on a player hit, dust on jumps and landings, a halo around each lamp. `?particles=0` turns them off. |
| (client rendering) | Bloom, ACES tone mapping and grading and a vignette (`?post=0` turns them off); sun shadows in three cascades (sharp near you, soft far away). Both are switchable in Settings > Display. |
| `client/sound.js` | The arena's sound, all made in code with `@engine/audio`: your shots in your ears, other players' shots placed where they fired, impacts, hit pings, footsteps for everyone (placed at their feet, one per stride), jump and landing, a hurt grunt, a chime for server messages and an ambient music loop. |
| (client lighting) | The sun casts shadows (`?shadows=0` to turn them off). Eight lamps sit above the pillars (point lights, with a glowing bulb each), faint by day and strong when a mod darkens the sky, and every shot flashes a light at the muzzle and at the impact. Decoration only: nothing in the simulation knows about it. |
| `mods/` | `low-gravity` (rules), `night-sky` (theme), `healing-aura` (script mod, runs confined and can only return commands). |

## The network model in short
- Inputs are one per tick: move axes, buttons, **quantized yaw and pitch**. Server and client both move the player from the quantized angle, so they compute the same result (replaying inputs from a server state is bit-identical).
- Snapshots carry x/y/z (2 mm), yaw, pitch, vertical speed, grounded, hue and health. The client reconciles against the state at the newest input the server has applied.
- A shot is a ray from the shooter's eye against the level's walls and the other players' body ellipsoids. The shooter tells the server which tick they were looking at; the server places bodies where *that client was shown them* (at most 250 ms back) and judges there. The client runs the same ray code and cooldown counting to show the tracer and hit at once; the server's event confirms or corrects it.
- Reconnect: the server issues a 128-bit session token in WELCOME. If a connection drops, the character stays in the world, frozen, for `resumeWindowMs` (15 s; `--resume`), keeping position, health and the weapon cooldown. The client retries with backoff (250 ms doubling to 4 s, 8 attempts), presents the token, and gets the same character back; replication and input numbering restart cleanly (full snapshot, sequence 1), so prediction stays in sync. A newer connection with the token replaces a half-open old one; a forged or expired token just creates a new player.
- Mods: data mods change whitelisted rule values within ranges (same on both sides, hash-verified before play); script mods return commands that the game validates against live state. A teleport command is refused if the destination overlaps geometry or the straight path to it crosses any.

- Players and bots collide with each other: after each tick the server pushes overlapping bodies apart on the ground plane (`server/separation.js`, at most 8 cm per tick, then out of walls). The shared movement step knows nothing of other players, so prediction is unchanged; a push shows up as a small ordinary correction.

## Tests
`npm test` runs `test/*.test.js` (geometry, events, input queue, prediction replay, end-to-end over simulated lossy links, lag compensation with and without, shot prediction, interest, mods, golden hashes). `node tools/arena3d-test.js` drives the real page in Chrome on both renderers with real key events.

## Not done
Vertical interest management (distance is measured on the ground plane), a room browser page (rooms are chosen by name in the URL).
